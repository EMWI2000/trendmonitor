Consequences for the pipeline:

1. Explicit `currency` per brand and `fx_to_dkk` in sources.yaml; `price_dkk` on every row.
2. `live_days` filter: keep a product only if ≥ 1 variant is available or it was published within
   120 days; otherwise outlet archives (Munthe, Herskind) dominate every metric.
3. Size detection accepts UK/EU prefixes and size in any option; colour-in-option1 stores work.
4. `exclude_types` / `exclude_tags` per brand for beauty, home, knitting patterns, men's, accessories.
5. `season_tag` extracted from tags (SS27, FW26, PS25, PF25, "SEASON - 264", "27 Pre Spring").
6. Structured brand tags (Stine Goya `print:Florals`, Munthe `SYSCOL - Brown`) already match the rule
   tagger's keywords; a per-brand tag parser can tighten this later.

## Follow-up the same day: Rabens Saloner and Kitri filters

One polite first-page read of `/products.json` per store (robots.txt, configured UA, 2 s delay), aggregates
only; the local snapshot had kept 37/364 Rabens products and 45/221 Kitri products with about 0 % available.

**Rabens Saloner** (250 products on page 1, 996 variants, 87 % available, every product had at least one
available variant, all published 2026-03-18 to 2026-10-07): 216 of 250 were dropped by `exclude_tags: "preloved"`.
The tag `preloved` sits on 200 of the 250 products, including new-in dresses, knits and jackets published
the same week, i.e. it marks eligibility for the brand's resale programme, not a pre-loved item. The regex
itself is applied correctly (per tag, case-insensitive); the word was wrong. Product types seen: blank (93),
ACCESSORIES (35), SKIRTS (25), PANTS (22), JACKETS (17), SWEATERS (16), JERSEY TOPS (13), SWIMWEAR (10),
BED LINEN & TOWELS (8), BEAUTY (8), FOOTWEAR (2), SHORTS (1). Structured tags carry the category instead
(`Rabens Saloner - WOVEN DRESSES`, `type_Dresses`, `type_jerseytops_woventops`); interior products belong
to the Rabens Apartment line (`vendor_interior`, `rabensfriendsapartment`, `type_textiles`, `type_brass`,
`type_decoration`, `RA - ...`). New rule: exclude by product_type (accessories, footwear, beauty, bed linen,
towels, jewellery, home, objects, candles, preloved) and by anchored structured tags
(`^vendor_interior$`, `^rabensfriendsapartment$`, `^type_(accessories|textiles|fragrance|bedlinen_towels|brass|decoration)$`);
`preloved` is no longer a tag exclusion. Expected yield on page 1 is roughly 180 products instead of 34.
No pre-loved product_type or vendor was visible on page 1; the product_type guard stays.

**Kitri** (221 products, 1,182 variants): 1 variant available, every variant carries a compare_at_price,
newest `published_at` 2026-07-03, oldest 2023-08-27, `updated_at` bumped daily (tag `StockMetaUpdated`).
Nothing was dropped by exclusions; 176 products were dropped by `live_days` and the 45 kept were kept
only through the 120-day window, all fully unavailable. The public feed is an archive-sale remnant rather
than the live shop (probably a separate storefront channel), so it cannot support sell-out tracking and
it made Kitri the top markdown alert in the first weekly report. Disabled in `sources.yaml` until a
re-probe shows available stock; re-enabling later would start with 1,181 restock/sold_out pairs if the
flag flips, so check the first snapshot by hand.
